# 马步 / 弓步角度规则提交与评测设计

版本：2026-11-01；适用：VisionEducation Windows 离线版。

## 教学目标与使用方法

学生在“量势成规 → 把动作特征，写成角度规则”中自主设置角度条件，然后在紧接着的“把你的规则，交给真实动作检验”中提交。选择哪一个动作对应马步、哪一个对应弓步，点击“提交规则并检验”。不要求先完成其他课时；本课文字反思关联本组已提交的规则评测记录，原有提膝高度差实验已移除。

教师进入工作台，选择课堂，在“角度规则自动检验”中查看学生规则。默认显示每位学生最新一次，可取消勾选查看全部历史；支持姓名/学号搜索、逐样本核对、规则 JSON 下载和完整报告下载。学生也能查看自己的历史结果，修改后再次提交。每次提交均保留独立快照，后续编辑不会覆盖之前的规则或成绩。

学生和教师均可在本模块查看“班级实时成绩榜”：显示本班所有已加入的小组/学生、最高正确率、最新一次成绩、最佳规则的宏 F1/覆盖率及提交次数。每个加入课堂的身份计为一组，同一小组使用一个代表身份提交。未提交者显示“尚未提交”，不分配名次。学生本组高亮并显示当前排名。

排名以当前验证集版本及摘要一致的历史最高正确率为准，同分并列，使用 1、1、3 的竞赛排名；提交较差的新版本不会降低已有最高成绩，但“最新一次”如实变化。所有人使用相同的 13 个样本，因此按正确数量排序等价于按正确率排序，不使用 F1 或提交速度打破同分。历史其他验证集版本不混入当前榜单。

成绩榜每 5 秒向教师电脑读取一次，当前组提交后立即刷新，也提供手动刷新。网页隐藏时暂停轮询，恢复可见时更新。网络失败会明确标记同步失败，保留上一份成绩并重试，不把旧成绩伪装成最新结果。榜单仅限同课堂成员及所属教师访问，仅展示组名与成绩摘要，不开放其他组的完整规则、学号、成员 token 或答卷。

正常课堂流程：教师启动本地系统、创建课堂 → 学生凭课堂码加入 → 拖点并设条件 → 明确马步/弓步对应 → 提交 → 对照错误样本和角度证据 → 修改并再次提交 → 解释变化原因。原有“保存草稿”和“导出规则”仍只处理本机草稿；收到服务器回执才算提交成功。

## 固定验证数据如何建立

正式集包含 **13 张不同底图的真人照片：马步 7 张、弓步 6 张，来自 8 个站点**。采集日期为 2026-11-01。没有把镜像、裁剪、加字或调色版本重复计数。逐图来源、下载链接、尺寸、原始字节 SHA-256、作者/许可状态、人工标签理由记录在 `data/stance-benchmark/sources.json`；候选剔除记录在 `rejected-candidates.json`。

采集时同时检查教学来源标注和实际下肢形态，排除半马步、仆步、线描图、严重遮挡和重复底图。一张 199×200 的弓步图虽动作标签明确，但提取后的后腿关节点明显错位，已按图像/关键点质量剔除并保留审计记录，替换为 UCL 论文中清晰且明确标注的 Gong Bu 照片。未依据学生规则是否判对来挑选图片，也没有手工移动关键点使规则“通过”。

正式样本保留正面、斜面、侧面和背面差异。两个马步在斜视下的二维膝角接近伸直，这类投影难例保留用于课堂讨论。Sarah Chang 的两张风格化高跟鞋照片只用于动作类别识别，不作为学校体育动作或穿着规范示范。

原图保存在开发电脑的 `data/stance-benchmark/source-images/`，可供教师核对；大多数未注明开放许可，因此原图、网页/PDF研究副本和原图拼图均不放到 public、GitHub 或免安装包。应用只使用派生关键点、骨架与必要来源索引。完整来源/许可清单随免安装包文档提供；需要公开原图时，应另行核实或取得相应授权。

## 图片到关键点：一次准备，课堂离线复用

开发侧使用 `scripts/prepare-stance-benchmark.py`：

1. 按清单校验原图 SHA-256，确认每张均有人工核对标记，拒绝完全重复图片。
2. 应用 EXIF 朝向；透明 PNG 合成在白底上，不删除原始水印。
3. 保持宽高比，将图片缩放到 640×640 输入范围，并用 RGB(114,114,114) 补边；BILINEAR 插值，转 RGB、NCHW、float32，像素除以 255。
4. 调用项目内固定 **YOLO26n-pose ONNX**，使用 ONNX Runtime CPU 1.22.0，人体阈值 0.25。正式原图均为单一示范主体，选检测置信度最高的人；模型本身输出端到端去重后的候选。
5. 撤销 letterbox 缩放与补边，恢复原图像素坐标；保存 COCO 17 点的 `[x, y, confidence]`，保留人体置信度、原图大小及模型 SHA-256。
6. 生成叠加骨架核对图供本地检查。正式运行数据写入 `lib/stance-benchmark.json`，冻结版本 `stance-web-coco17-v1`，附规范化内容 SHA-256。学生不能选择或上传替代验证集。

正式集全部两侧髋、膝、踝的置信度达到 0.5。对学生选择的任意三点角度仍逐点检查置信度，不能以低置信坐标硬算。将来补充的数据即使出现低置信关键点，也保留“信息不足”结果，不通过移除样本提高分数。

课堂只加载固定关键点，不重新下载图片，也不让教师电脑重复运行 13 次 YOLO。学生规则的比对、计分与数据库保存都在教师电脑服务端完成，教师无须安装 Python。

## 归一化与角度计算

设原图大小为 W×H，取 S=max(W,H)，同时令 x'=x/S，y'=y/S。这里对两个坐标轴使用相同尺度，以保持二维角度。**不能分别用 x/W、y/H 计算角度**，因为非方形图片会被拉伸，改变夹角。

三点 A、B、C 中 B 为顶点：u=A−B，v=C−B，θ=acos(clamp((u·v)/(|u||v|),−1,1))×180/π。角度范围 0–180°。任一点置信度小于 0.5、坐标非有限或与顶点重合时，角度不可计算。实际判断使用未四舍五入的数值；界面角度显示到 0.1°。边界沿用编辑器的 1e−9° 浮点容差。

这个处理对平移、统一缩放和画面内旋转保持角度一致；它不恢复深度，也不消除人体转身、透视或遮挡带来的二维投影变化。没有训练均值/方差，也没有根据验证集学习任何归一化参数。

## 规则执行与五种结果

服务端和编辑器使用同一个 `AngleRules` 引擎。支持 ≥、≤、>、<、闭区间、近似相等及容差；同一情况中的条件为 AND，不同情况为 OR。空情况不当作自动满足。提交时要求两个不同、已启用且至少有一条有效条件的动作；其他动作保留在规则原文中，但不参与此次马步/弓步二分类评测。

| 结果 | 判定 |
| --- | --- |
| 马步 / 弓步 | 对应规则通过，另一规则明确不通过 |
| 规则冲突 | 两类同时通过；不按动作顺序强行选一个 |
| 未匹配 | 两类都明确不通过 |
| 信息不足 | 有规则因必需角度不可计算仍可能通过；即使另一类已通过也不强行给出唯一标签 |

对 AND 中已经明确不满足的情况，不会仅因其他条件缺点就标记为未知；对 OR 中已有明确通过的情况，其他未知情况不影响该动作通过。这与编辑器逐条解释一致。

## 评价指标

以全部 13 个样本为分母，冲突、未匹配、信息不足均不算正确，不从分母删除。

| 指标 | 定义与用途 |
| --- | --- |
| 总正确率 Accuracy | 正确动作判断数 / 全部样本数 |
| 有效识别覆盖率 Coverage | 唯一且信息充分的马步或弓步判断数 / 全部样本数；判断可能仍然错误 |
| 每类精确率 Precision | 此类判断正确数 / 所有被判断为此类的样本数；无此类预测时定义为 0 |
| 每类召回率 Recall | 此类判断正确数 / 真实属于此类的样本数；拒识和冲突计入漏检 |
| 每类 F1 | 2PR/(P+R)，分母为 0 时取 0 |
| 宏平均 F1 | 两类 F1 的平均值，避免 7:6 样本量差异掩盖弱类 |
| 平衡正确率 | 两类召回率的平均值，完整 JSON 报告提供 |
| 已识别样本正确率 | 正确数 / 有效识别数；无有效识别时为 null，不能替代总正确率；完整 JSON 提供 |

界面提供 2×5 混淆矩阵：行是真实马步/弓步，列是马步、弓步、冲突、未匹配、信息不足。逐样本记录真实标签、判断、左右膝角、骨架、每个角度条件及不可计算原因。教师可据此区分阈值不合适、视角局限、规则冲突和检测误差。

项目原有示例规则未经针对本集优化：两膝都 <155° 判马步；一膝 <155° 且另一膝 >165° 判弓步，含左右两种情况。冻结集实测为 **9/13 正确（69.2%）**、覆盖率 **84.6%**、宏 F1 **0.748**。马步召回率 4/7，弓步召回率 5/6；未匹配 2 个。完整基线见 `data/stance-benchmark/baseline-report.json`。这些是示例规则的结果，不是学生成绩，也不是 YOLO 的人体检测准确率。

这是允许学生反复调规则的教学验证集，不能再称为独立盲测集。13 张图片且来源人物可能相关，不足以估计普适识别能力；若用于正式教学研究，应另建未见过的人物、拍摄视角与学校环境的独立测试集。本功能评估动作类别识别，不给出武术动作规范达标评分。

## 服务端、持久化与权限

新增迁移 `0002_angle_rules.sql` 和 `rule_entries` 表：保存记录ID、课堂ID、成员ID、验证集版本与摘要、完整规则、动作对应、完整评测、正确数、总数、正确率和时间。每次提交为 INSERT，不覆盖旧记录；离线启动自动应用新增迁移，原有课堂/答卷/模型保留。规则记录纳入原有 SQLite 备份，无需额外文件存储。

| API（前缀 /api/classroom） | 功能 |
| --- | --- |
| GET /rules/benchmark | 返回验证集来源及计分说明，无原图 |
| POST /rules | 学生提交规则，服务端校验并重算，返回保存回执 |
| GET /rules/mine | 当前学生的提交历史摘要 |
| GET /rules/board | 当前学生所属课堂的实时成绩榜；不能自行指定其他课堂 |
| GET /rules/board?classId=… | 所属教师查看指定课堂的实时成绩榜 |
| GET /rules/:id | 当前学生自己的规则与完整报告 |
| GET /rules/inbox?classId=… | 课堂所属教师查看全班规则历史摘要 |
| GET /rules/:id?teacher=1 | 所属教师查看完整快照、导出规则与报告 |

复用课堂成员 token 和教师所属关系校验。学生不能访问别人的记录或教师接口，另一教师不能跨课堂读取。服务端不采信学生传来的正确率、标签、关键点或验证集；仅接受经过校验的规则和动作映射。POST 要求同源 Origin、JSON，流式读取限制 96 KB；每个学生每个课堂最多保存 50 次，SQL 原子限制避免并发超额。课堂结束收件后禁止新增，历史仍可阅读。不会执行学生提交的任意代码。
